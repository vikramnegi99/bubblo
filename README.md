# BUBBLO — Storefront

Make Moments Magical.

A complete, responsive, accessible, conversion-focused customer-facing e-commerce
frontend for BUBBLO — a premium bubble-gifts brand for India. Cash On Delivery only.

Live site: https://vikramnegi99.github.io/bubblo/

## How orders reach the business

Every order placed on the site is emailed to **mrvickybusines@gmail.com** — no
server, no account, no cost. This works from static hosting because the
customer's own browser sends the order.

- The email relay is configured in `assets/js/config.js` → `order.emailEndpoint`.
- **One-time step:** the very first order triggers an *activation* email to that
  inbox. Click **Activate** in it once, and every order after that is delivered
  automatically.
- As a guaranteed backup, the order confirmation page also has a
  **"Send this order on WhatsApp"** button that opens WhatsApp pre-filled with
  the full order, so an order is never lost even before the email is activated.

To send orders to a different address, change `order.email` **and** the address
inside `order.emailEndpoint`.

## Running it locally

Because links use directory routes, preview with a tiny local server (not `file://`):

```bash
python3 -m http.server 8000
# then open http://localhost:8000/
```

## Configuration — `assets/js/config.js`

One file holds everything the business may want to change:

- **Contact** — WhatsApp number, email, prefilled message (exact supplied values).
- **Order** — the inbox that receives orders and the email relay endpoint.
- **Campaign** — `campaign.end` is the single fixed campaign end timestamp for
  BUBBLE MEGA DAYS. The countdown is computed from this absolute instant, so it
  never resets on reload and shows an "ended" state once it passes.
- **Shipping** — no shipping fee is invented. The cart shows a neutral
  "to be confirmed" state and the total equals the subtotal.
- **Storage keys** — cart and orders.

## Order tracking

`/track-order` currently looks up orders stored in the customer's own browser, so
it works for the person who placed the order on that device. Cross-device tracking
(any customer, any phone) needs a backend that stores orders — for example a
Google Sheet via Apps Script. `submitOrder()` and `lookupOrder()` in
`assets/js/app.js` are the two clearly-marked integration points for that upgrade.

## Intentionally excluded

No admin panel/dashboard, no online payment gateway, no UPI/card/wallet, no OTP or
SMS/phone verification, no account or login requirement, no Meta Pixel / Conversions
API / ads tracking, no fabricated reviews, ratings, stock, sales or customer counts,
and no invented product specifications, accessories, warranties or delivery promises.

## Assets

All product, campaign and logo imagery is delivered from the supplied Cloudinary
collections via individual, optimised asset URLs (`f_auto,q_auto,c_limit,w_…`) —
collection URLs are never used directly as image sources. Images use aspect-ratio
containers to avoid layout shift, have graceful fallbacks, and Pink/Blue and
product-to-product assets are kept strictly separate.

## Accessibility

Semantic landmarks, keyboard-operable navigation and gallery, visible focus states,
labelled form fields with accessible validation, ARIA only where needed, meaningful
alt text, screen-reader status messages for cart and order state, and full
`prefers-reduced-motion` support.
